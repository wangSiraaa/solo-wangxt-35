# WalkReach · 步行可达性分析（纯 Web / 无外部密钥）

面向社区规划的步行可达性分析工具：**在不传出任何住址信息的前提下**（全部计算在浏览器本地完成），
分析从某起点出发、沿真实路网步行可达的公共设施。

## 技术栈

| 关注点 | 方案 |
| --- | --- |
| 界面 | Svelte 4 + TypeScript（Vite） |
| 地图渲染 | MapLibre GL JS，**内联本地样式**，不请求任何外部瓦片/字形/密钥 |
| 图算法 | Graphology 有向图（单行边只建一个方向） |
| 路网求解 | Web Worker（建图、吸附、Dijkstra 等时圈、路径回溯） |
| 场景持久化 | IndexedDB（路网 + 设施 + 参数 + 起点） |

## 运行

```bash
npm install
npm run dev      # 开发
npm run build    # 产物（纯静态，可任意托管）
npm run check    # 类型检查
```

打开后自动加载**演示数据**（代码内生成的小镇：河流、两座桥、单行街、台阶小径、
断开的小巷、数据范围边界），无需任何网络与密钥。

## 功能与判定逻辑

- **沿道路计算**：等时圈是 Dijkstra 在路网图上扩散的结果（按时间带着色的可达路段，
  预算耗尽处沿边截断），不是圆形缓冲；设施路径沿道路重建。
- **单行通行**：`oneway=yes/-1` 只建对应方向的有向边，起点离开单行道也受方向限制。
- **台阶禁行**：`highway=steps` 不进入可通行图，但保留用于诊断——
  若设施“仅台阶可达”，会明确报告为 `仅台阶相连`，而不是笼统的不可达。
- **断开路段**：连通分量在可通行图上计算，与主网断开的路段在地图上紫色高亮；
  落在断开分量上的设施报告为 `路网断开，不可达`。
- **吸附透明化**：设置起点时展示最近 5 条候选边（距离、投影点、两端候选节点），
  由用户确认；若“点击点→投影点”连线穿过水体屏障，候选会标红警示，
  自动选择时优先不穿屏障的边——避免吸到河对岸。
- **数据缺失 ≠ 不可达**：
  - 设施在数据边界之外 → `超出数据范围，无法判定`；
  - 设施距最近可通行道路超过 100 m → `疑似数据缺失，无法判定`；
  - 导入数据未提供边界时，按路网包围盒近似并在界面上明确标注。

## 数据格式

- 路网：`FeatureCollection<LineString>`，属性支持 `name`、`highway`（`steps` 禁行）、
  `oneway`（`yes`/`-1`/`no`）、`bridge`。
- 设施：`FeatureCollection<Point>`，属性 `id`、`name`、`category`（缺失时自动补全）。
- 水体（可选）：`Polygon/MultiPolygon`，作为吸附屏障。
- 数据边界（可选）：`Polygon/MultiPolygon`，界定“数据缺失不可判定”的范围。
