# WalkReach · 步行可达性分析（纯 Web / 无外部密钥）

面向社区规划的步行可达性分析工具：**在不传出任何住址信息的前提下**（全部计算在浏览器本地完成），
分析从某起点出发、沿真实路网步行可达的公共设施。支持**上学时段**场景：
定时开放的过街通道、分时段封闭的道路、必经接送点与停留。

## 技术栈

| 关注点 | 方案 |
| --- | --- |
| 界面 | Svelte 4 + TypeScript（Vite） |
| 地图渲染 | MapLibre GL JS，**内联本地样式**，不请求任何外部瓦片/字形/密钥 |
| 图算法 | Graphology 有向图（单行边只建一个方向） |
| 路网求解 | Web Worker（建图、吸附、静态/时变 Dijkstra、路径回溯） |
| 场景持久化 | IndexedDB；可导出/导入 JSON（**保留时区与开放日历**） |

## 运行

```bash
npm install
npm run dev        # 开发
npm run build      # 产物（纯静态，可任意托管）
npm run check      # 类型检查
npm run test:smoke # 静态求解冒烟测试
npm run verify:td  # 时变求解交叉核验（小图穷举对照）
```

打开后自动加载**演示数据**（代码内生成的小镇：河流、桥、单行街、台阶小径、
断开小巷、限时桥/天桥、数据边界），无需任何网络与密钥。

## 时刻模式（时变 FIFO 路段模型）

- **边成本 = 出发时刻的函数**：`arrive(t) = t + wait(t) + tt`。
  每条边可挂 `schedule`（`open-only` 定时开放 / `closed-during` 时段封闭），
  窗口按场景日历（`calendar.timezone` + `calendar.date`）的本地时间与星期解释，支持跨夜。
- **限定 FIFO 模型**：通行时间恒定、封闭时允许在入口等待到下次开放。
  该模型下到达函数单调不减，标号设定的时变 Dijkstra 正确。
- **检测并拒绝非前提数据**（`td.ts` 校验，加载时执行；有错则禁用时刻模式求解，
  **不会退回普通最短路**）：
  `wait=false`（封路即不可走，到达函数非单调）、窗口重叠、零长度窗口、
  非法时刻/星期、零通行时间、无效时区/日期；另有时界内到达函数单调性抽查兜底。
- **必经接送点两段行程**：第一段到接送点的**实际到达时刻 + 停留分钟**作为第二段出发时刻；
  两段等时圈分别渲染（绿/紫），拖动出发时刻滑块可看到第二段随之收缩/改道。
- **等待可视化**：等时圈层面上标记所有发生等待的节点（橙色点，点击看详情），
  选中设施的路径上标出每次等待/停留的位置、时刻与时长。
- **结果一致性**：每次求解带序号，Worker 返回的旧结果直接丢弃，
  时间滑块快速拖动不会混入上一次结果。

## 演示案例（默认 07:30 出发，均可由时间滑块复现）

1. **刚好赶上关闭**：北二街天桥 07:51 关闭，默认行程 07:50 到达（余量约 1 分钟）。
2. **等待优于绕路**：永安桥 07:31–07:36 封闭，到达时等待约 2 分钟，
   比绕青山桥（约 20 分钟）更优——算法自动选择等待。
3. **第一段延误影响第二段**：出发改到 07:34，第一段错过天桥窗口，
   回程又遇永安桥 07:45–08:30 管制，到达时间被放大约 9 分钟。

`npm run verify:td` 对上述案例做断言，并用**小图穷举**（简单路径枚举 + 精确仿真）
交叉核验时变 Dijkstra 与两段行程的正确性（9 个出发时刻 × 4 个节点、5 组两段行程，零偏差）。

## 静态路网语义（沿用）

- 等时圈沿路网计算（非圆形缓冲）；单行、台阶禁行、断开路段参与计算；
- 吸附展示候选边/节点与距离，连线穿水体的候选标红，避免吸到河对岸；
- 数据范围外 / 离路网过远的设施判定为「无法判定」，不解释为确定不可达。

## 数据格式

- 路网：`FeatureCollection<LineString>`，属性：`name`、`highway`（`steps` 禁行）、
  `oneway`（`yes`/`-1`/`no`）、`bridge`、`schedule`（可选，见下）。
- 设施：`FeatureCollection<Point>`，属性 `id`、`name`、`category`（缺失自动补全）。
- 水体 / 数据边界（可选）：`Polygon/MultiPolygon`。
- 场景导出 JSON：`{ format: 'walkreach-scenario', version: 2, calendar: { timezone, date }, roads, facilities, settings, originPoint, viaPoint, ... }`。

```jsonc
// 边属性 schedule 示例：工作日 07:31–07:36 封闭（可等待）
"schedule": {
  "mode": "closed-during",          // 或 "open-only"（仅窗口内开放）
  "windows": [{ "days": [1,2,3,4,5], "open": "07:31", "close": "07:36" }]
}
```
